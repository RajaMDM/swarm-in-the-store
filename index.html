      Master data checks

      Tier 1 · Structural integrity

      Is each file well-formed and internally consistent? A failure here blocks the run.

        Tier 2 · Operational sync

        Does the system of record agree with the shop floor (planogram, POS register list)? A failure here is a warning: the store still opens, and pays for it.

          Structural checks all pass, so the systems look healthy. Operational sync says otherwise, and the shop floor pays the price.

          How to read it

          1. Press Run. Shoppers enter at the bottom, go where the signage points, queue where the board calls them, and leave.
          2. Turn on the heatmap. The hotspots were never coded. They emerge from local crowd avoidance.
          3. Pull a lever. Move the promo stand, close a checkout or raise arrivals. Same seed, same shoppers, different store.
          4. Break one thing at a time. Tick a defect and watch Tier 2 turn amber while Tier 1 stays green. Then run the defect matrix to see whether the defects add up, compound or mask each other.

          How defects work: each one is a patch to a system-of-record file in data/defects.json. The engine has no "dirty" mode; it reads whatever the masters say. Illustrative model, not calibrated to any real store; prices are placeholders. All names and data are fictitious.
